## 二、规则硬约束速览（必知红线，违反即 `Needs repair` 进不了评审）

1. **只认真实公开 / 已授权数据**，禁止编造；所有陈述须带证据标记 `[source:...] [standard:...] [depth:...] [data:geometry/xxx.geojson#feature] [metric:...]`。
2. **边界分官方 / 临时两类**：官方边界 `official_boundary=true`；临时边界必须 `geometry_role="provisional_constraint"`、`official_boundary=false`，明确标注"非官方红线、非法定规划"，组织者数据缺口不扣分但不等于已获批。
3. **所有空间方案只能是"概念性建议 / 参考方案 / 供专业团队深化"**，严禁写成"法定规划、政府已批准、确定实施、投资承诺、工程可行、地块级拆改结论"。
4. **六类 agent 任务硬指标**（必须变成 `proposal.md` 可读内容）：命名/Logo/识别系统；5–8 个全球 AI 生态案例；≥10 张场景卡；≥3 个产业测试/验证场景；≥5 类用户画像；≥3 处 AI 朝圣地标或荣誉展示节点；文化叙事；长期全球 AI 活动/社区运营机制。
5. **每个公告任务（1.3/1.4/1.5）与 agent 任务（agent.1–6）都要进 `compliance_matrix.json` 逐项覆盖**，缺一不可。
6. **5 张必填图必须"演示级城市设计图"**（非 debug / 非纯方格块 / 非未样式化 GIS 截图）：`site-overview` `land-use-structure` `key-areas` `mobility-bluegreen` `metrics-evidence`，须由同一份 GeoJSON/metrics 派生。
7. **`visual/index.html` 必须离线静态**：禁止 CDN、远程地图瓦片、外部脚本/字体、iframe、表单、API、追踪代码。
8. **包状态必须是 `package_state="ready_for_review"`**；脚手架生成的是 `scaffold`（故意无效），必须替换全部占位内容、删除 `SCAFFOLD-DRAFT` 标记、跑 `finalize` 后才能提交。

## 三、必需产物清单（对标标杆方案，逐文件）

| 文件 | 角色 | 落朵产出方 | 关键要求 |
|---|---|---|---|
| `manifest.json` | 包清单 | Code | 列全文件 + SHA-256，含 package_type/state/agent 身份 |
| `agent.json` | Agent 身份卡 | 总控 | agent_id/name/model/operator_github + 生成披露声明 |
| `proposal.md` | 主报告（可读） | 研究+文案 | 中英双语、证据引用、覆盖全部任务、非矩阵堆砌 |
| `proposal.en.md` / `proposal.zh.md` | 双语对照 | 研究+文案 | 章节/指标/图位对齐，缺译仅非阻断警告 |
| `geometry/*.geojson` | 空间数据 | Math+Code | site_boundary/land_use/key_areas/green_space/public_space/buildings/roads/phasing/ai_nodes，EPSG:4326，投影 EPSG:4548 复算指标 |
| `metrics.json` | 指标 | Math | 站点面积、用地分类面积、总建面、容积率、密度、绿/公/路占比、分期面积等，可复算或标 `unknown` |
| `assumptions.json` / `sources.json` | 假设/来源 | 数据 | 未知项按 `{status:"unknown",...}` 形状；来源须来自公开源注册表 |
| `compliance_matrix.json` | 合规矩阵 | 质检 | 逐条映射 1.3/1.4/1.5 + agent.1–6 到章节/图层/指标/图纸/来源 |
| `standard_matrix.json` `/design_depth_matrix.json` | 标准/深度 | 质检 | 覆盖强制专业标准、强制设计深度项须 `complete` |
| `self_check.json` `/risk.json` | 自检/风险 | 质检 | self_check 必须 PASS；风险含法律/官方声明边界 |
| `assets/figures/*.png` | 5 张必填图 | 视觉 | 演示级城市设计图，从同一 GeoJSON/metrics 生成 |
| `report/proposal.html` | 离线阅读版 | 视觉 | 本地图片、离线、含 5 图 |
| `drawings/*.pdf` | A3 手册 / A0 展板 | 视觉 | a3-booklet.pdf、a0-boards.pdf |
| `visual/index.html` | 离线仪表盘 | 视觉 | 概览图/三级范围/核心区/用地/交通步行/蓝绿/建筑/AI节点/指标/合规/自检/来源，数值须与 metrics.json 一致 |

## 四、落朵 AI 军团多 Agent 协同分工

> 军团本体偏理工/工程/零售/医疗（总控 SkyDuo + 理科 8 + 工程 2 + 软件 2 + 业务 2），无专门"城市规划"Agent。本次以**总控协调 + 临时编组"城市规划特遣队"**方式作战。

1. **总控 SkyDuo（天朵）**：任务编排、进度统筹、最终自检口径拍板、`agent.json` 身份与生成披露定稿。
2. **Code（软件）**：运行官方脚手架与脚本链、生成/校验所有 JSON、GeoJSON、离线 HTML/PDF，组装 `manifest` 哈希。
3. **Math（理科）**：EPSG:4548 投影、用地分区面积复算、全部 `metrics.json` 指标可复算、拓扑自检（无重叠/无空隙）。
4. **Safe（软件）**：合规边界把关——provisional 标注、概念性声明、法律/版权边界、risk.json 与 generation_disclosure 审核。
5. **Retail + Health（业务）**：产出 AI+商业、AI+医疗、AI+康养场景卡与验证场景（真实落地能力，差异化亮点）。
6. **Material / Thermal（理科）**：低碳/气候公地、能源-水-数据成本转公共回报等绿色场景（对标上榜的 SHADE THE CLOUD 方案）。
7. **研究/文案（总控兼任或外调）**：全球 5–8 案例研究、命名/Logo/视觉规范、文化叙事、≥5 用户画像、≥3 朝圣地标、长期运营机制——**本项为能力缺口，需补"城市设计审美 + 案例研究库"**。
8. **视觉（可由 Code+外部工具承担）**：5 张演示级图、report HTML、visual/index.html 离线仪表盘。
