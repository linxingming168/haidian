# 落朵智能体之城 · AI 产业测试验证场景（3 个）

> **强制表述边界**：以下均为"测试验证 / 试点设想"，**非已批准运营**；不将概念设想写成已确定政府决策或已部署能力 `[agent.3.forbidden]` `[boundary_clause]`。所有验证均设人工复核开关与数据最小化原则 `[charter.10]`。

## V-01 城市感知底座 EMQX 数据验证

- **对应场景**：S-09 应急安全、S-10 低碳治理
- **输入**：
  1. 在重点区部署的 EMQX cj 节点（落朵真实运行的数据采集能力）回传 anonymized 环境/设施状态（温湿度、空气质量、人流密度、设施在线状态）；
  2. 注入若干"异常"测试用例（如模拟积水、设施离线、异常聚集）；
  3. 人工复核员账号在线，开关置为"开启"。
- **预期输出**：
  1. 系统生成"待人工确认"态势卡片，标注异常类型、位置（概念网格）、置信度；
  2. 推送至运营方与网格工作台，**不自动执行**任何强制动作；
  3. 低碳侧输出 anonymized 用能—人流趋势建议（错峰照明/灌溉排期）。
- **验收标准**：
  1. 异常事件 100% 进入人工复核队列，零自动处置；
  2. 误报率（经人工判定为非异常）≤ 预设阈值，且可解释；
  3. 全程无个人身份信息（PII）采集与留存，数据最小化可审计；
  4. 复盘日志可导出，符合可审计、可复盘要求 `[charter.10]`。
- **风险**：
  1. 感知误报引发运营过载 → 缓解：阈值可调 + 人工复核开关 + 灰度投放；
  2. 设施离线导致盲区 → 缓解：冗余节点与健康自检；
  3. 数据边界争议 → 缓解：仅 anonymized 环境量、禁用个人行为数据。

## V-02 康养机器人社区陪伴试点

- **对应场景**：S-04 蓝绿康养、S-06 社区养老
- **输入**：
  1. 在 AI 原点社区选取自愿参与的长者样本，签署授权；
  2. 康养机器人（扁鹊）提供陪伴、用药/复诊提醒、活动邀约；
  3. 家属端侧经授权接收关怀同步；异常生成"待人工确认"工单。
- **预期输出**：
  1. 陪伴打卡与提醒触达率统计（授权范围内）；
  2. 异常工单推送社区驿站与家属，由人工处置；
  3. 仅输出聚合活动参与度，不输出个人健康明细。
- **验收标准**：
  1. 提醒触达率 ≥ 预设目标，且用户可一键撤回授权；
  2. 异常工单 100% 人工处置闭环，零自动紧急干预；
  3. 个人数据本地留存、可撤回、可删除，符合数据最小化；
  4. 试点报告标注为"概念/试点"，非已批准长期运营 `[agent.3.forbidden]`。
- **风险**：
  1. 技术不成熟被误读为已部署 → 缓解：所有物料标注"试点设想"；
  2. 适老化交互门槛 → 缓解：家属协同 + 驿站兜底；
  3. 隐私顾虑 → 缓解：端侧优先、授权可撤回、不采集健康明细。

## V-03 无人零售高峰承载压力测试

- **对应场景**：S-05 无人零售
- **输入**：
  1. 在重点区布设挺盈宝 tyb 无人商店与易得 yd 售货机（落朵真实生态能力）；
  2. 注入高峰订单波次（轨道到站波次 + 公共空间活动峰值）；
  3. 落朵大脑 jt 做库存与补货编排，运营方在人工复核下确认排班。
- **预期输出**：
  1. 高峰缺货率、订单满足率、补货周转时长统计；
  2. 10 分钟补给可达覆盖率测算（概念示范段范围）；
  3. 仅处理订单与库存数据，不涉及人脸身份绑定。
- **验收标准**：
  1. 高峰订单满足率 ≥ 预设目标，缺货率可控；
  2. 补货排班 100% 经运营方人工复核确认；
  3. 零人脸身份绑定，符合隐私与人工复核边界 `[charter.10]`；
  4. 测试结论标注为"压力测试设想"，非已批准运营规模 `[agent.3.forbidden]`。
- **风险**：
  1. 高峰运力不足 → 缓解：动态波次 + 运营方复核兜底；
  2. 点位承载超限 → 缓解：PR 征集优化、概念示范段限定；
  3. 误读为已铺开运营 → 缓解：所有结论标注"测试验证"。

## 验证总原则

- 三验证均**不替代正式审批**，成果为"可供专业团队深化研究"的输入 `[boundary_clause]` `[charter.3]`。
- 全部感知/决策类动作保留**人工复核开关与人工否决权**，数据最小化、anonymized，不触碰个人隐私与非公开数据 `[charter.10]` `[agent.3.forbidden]`。
- 验证复盘以 city-as-repo 方式沉淀，被采纳优化记入荣誉墙 `[charter.8]` `[charter.9]`。
